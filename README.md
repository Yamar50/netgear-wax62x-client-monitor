# NETGEAR WAX62x Client Monitor

Home AssistantからNETGEAR WAX625 / WAX628のローカル管理APIを読み、Wi-FiクライアントをMACアドレスで追跡するカスタム統合です。メーカー公式の統合ではありません。

## 機能

- APをまたいで移動しても同じMACを同じデバイスとして扱います。
- HAの設定画面でAPの追加・編集、登録する端末、取得間隔を変更できます。
- 接続状態、AP、SSID、IP、周波数帯、チャンネル、通信方式、RSSI、送受信速度・量、接続時間、暗号化方式、PMF、最終観測時刻を表示します。
- `HostName`は任意のテキストエンティティです。AP取得で上書きせず、再起動後も維持します。エンティティIDは変更しません。
- 全クライアントの取得済みキャッシュを認証付きAPIで提供します。外部の表示プログラムからAPへログインする必要はありません。
- 外部の保守処理はHAから排他的な「使用予約」を取得できます。予約中はHAのAP収集が止まります。

APからの取得に失敗した場合や情報が古い場合、接続状態は利用不可になります。全APから正常に取得できて初めて、見つからない端末を切断として扱います。これはWi-Fi接続状態であり、人物の在宅を直接保証するものではありません。

## HACSからインストール

1. HACS → 右上のメニュー → カスタムリポジトリ。
2. `https://github.com/Yamar50/netgear-wax62x-client-monitor` を種類「統合」で追加し、ダウンロード。
3. Home Assistantを再起動。
4. 設定 → デバイスとサービス → 統合を追加 → **NETGEAR WAX62x Client Monitor**。
5. APのアドレス・管理者名・パスワードを入力。自己署名証明書の場合は、そのAPの「HTTPS証明書を検証する」を外す必要があります。
6. 統合の「設定」から残りのAPを追加。
7. 既存の収集処理を停止するか、下記の使用予約に対応させてから「定期取得」を有効化。
8. 取得後、「クライアントを登録」でエンティティにする端末を選択。

**初期状態では取得は停止しています。** 設定画面で登録しただけではAPへログインしません。取得間隔の既定値は600秒、設定可能範囲は300～86400秒です。複数のHAや管理スクリプトを同じAPへ無調整で接続しないでください。同じAPをIPと別名で重複登録しないでください。

## 外部から読む

HAの管理者ユーザーのアクセストークンを使い、`GET /api/netgear_wax/snapshot` を呼びます。これはキャッシュ参照で、APログインを起動しません。`schema_version`は1です。

- `clients`：MACをキーにしたクライアント情報。`connected`は`true` / `false` / `null`。
- `aps`：APごとの取得状態・稼働時間・接続台数・観測時刻。
- `updated_at`：最後の収集完了時刻。`generated_at`はAPI応答作成時刻なので、情報の鮮度判定に代用しないでください。
- `access`：収集中または外部予約中かどうか。有効期限と種類を含み、予約トークンは含みません。

`tools/export_snapshot.py`はJSON、`tools/export_tsv.py`は既存WAXモニター形式のTSVを原子的に出力します。TSV側では従来表示との互換性のため、未確認も`Disconnect`表示にし、AP取得状態を別途出力します。在宅判定にはHAエンティティまたはJSONの三値を使ってください。

外部ツールはPython 3.9以降で動作します。HAへ接続できない場合も、既存TSVと状態ファイルがあれば過去の接続を未確認として表示し、観測時刻は更新しません。既存のsyslog処理などが同じTSVを上書きしないよう、書き込み元をこのエクスポーターに統一してください。

設定ファイルの例（Gitへ入れないローカルファイルとして保存）:

```json
{"ha_url":"http://homeassistant.local:8123","token_file":"/path/to/private-ha-token.txt"}
```

## APの使用予約

`POST /api/netgear_wax/reservation` を同じHA管理者トークンで呼び出します。

```json
{"operation":"acquire","duration":600}
```

取得成功時は`token`・`expires_at`・`duration`を返します。HAが取得中、または別の予約が存在する場合はHTTP409です。取得と使用権の確保はHA内部で原子的に行い、状態を確認してからログインする方式の競合を防ぎます。予約は全AP共通です。

```json
{"operation":"renew","token":"取得時の予約トークン","duration":600}
```

```json
{"operation":"release","token":"取得時の予約トークン"}
```

- 予約はディスクへ保存してから応答し、HA再起動後も有効期限まで維持します。
- 有効期限は120～900秒。外部処理は**期限より前に確実にAPアクセスを終える必要があります**。
- 別ユーザー・誤ったトークン・期限切れの予約で更新や解放はできません。
- HA不通・予約失敗ならAPへ接続しないでください。「使用中」エンティティの読み取りだけでは予約になりません。
- HAのログアウトが確認できない場合は、最大1時間の保守的な待機を残します。

付属のラッパーは予約成功後だけ子プロセスを起動し、30秒ごとに予約を更新します。更新失敗や実行時間超過時には子プロセスグループを停止します。通常終了時のみ予約を解放し、異常終了時は期限切れを待ちます。

```sh
python3 tools/with_reservation.py --config /path/to/private-config.json --timeout 240 -- node /path/to/ap-maintenance.js
```

子スクリプトはログアウトを`finally`で行い、ログアウト失敗を成功終了として扱わないようにしてください。AP設定変更中に強制停止すると中間状態が残る可能性があるため、実行時間制限には余裕を持たせ、既存の復旧手順を維持してください。

## HostNameを設定

HAのアクション `netgear_wax.set_hostname` に`mac`と`hostname`を指定します。空文字で任意名を解除し、APから取得した名前へ戻せます。AP由来の名前は別の診断センサーで確認できます。

```yaml
action: netgear_wax.set_hostname
data:
  mac: "02:00:00:00:00:01"
  hostname: "Family phone"
```

## 検証と制限

Home Assistant 2026.10.4 / Python 3.14で開発しています。テストは架空のAP・端末データを使用します。

```sh
python -m pytest -q
ruff check .
```

対象はWAX625 / WAX628です。他機種・全ファームウェアの互換性は未確認です。APの非公開管理APIの変更で動作しなくなる可能性があります。5GHz電波の実測監視や自動チャネル変更はこの統合に含まれません。既存の保守スクリプトとは使用予約で調整できます。

認証情報はHAの設定、取得済みの端末情報・任意名・予約はHAの`.storage`へ保存します。これらを含む診断情報や設定ファイルを公開リポジトリへ投稿しないでください。
